# 사용자 입력 기반 체험 환경

## 목표

`?demo=1`은 빈 개인·팀 작업공간에서 시작한다. 사용자가 입력한 VM, Serverless, Database, Apps, 팀 및 관리 요청을 브라우저에 저장해 화면 이동·새로고침·역할 전환 뒤에도 같은 상태로 조작한다. 백엔드 API가 제공하는 실서비스 경로는 유지한다.

## 범위

- 기존 Figma 시드는 별도 명시적 시나리오에서만 사용한다. 기본 체험에는 사전 생성 자원·신청·알림이 없다.
- 생성·수정·삭제·승인·거절·연장 등은 클라이언트 상태에서 서로 일관되게 반영한다. 실제 서버 작업이 아닌 동작은 사용자에게 오해를 주지 않도록 체험 환경으로 표시한다.
- V1에서 준비할 VM 약 10개의 공개 SSH 호스트·포트·계정을 설정으로 받아, 기존 계정별 생성 한도 검사에 통과한 요청에 생성 순서대로 슬롯을 배정한다. 준비된 VM 풀의 크기는 계정별 한도가 아니다. 설정되지 않은 슬롯에는 작동하지 않는 명령어를 만들어 표시하지 않는다.
- 클라이언트 저장은 브라우저 간 중복 배정을 방지하지 못한다. 공유 배정은 서버 측 기능이 준비되기 전까지 보장하지 않는다.
- Figma 디자인과 반응형 상태를 유지하고 학생·관리자 역할에서 주요 여정을 직접 검증한다.

## 제한

실제 SSH 연결 검증은 V1 VM 풀의 접속 정보가 제공된 뒤 수행한다. `main` 도메인의 백엔드 CORS 검증도 사용자 통보 뒤 수행한다. 변경은 작업 브랜치에서 `develop`으로 먼저 올리고, 검증 후 `develop`을 `main`에 반영한다.

## 외부에서 준비할 항목

- V1 VM 풀: 현재 계획은 약 10대다. 각 VM의 공개 호스트·포트·계정만 설정에 입력한다. SSH 인증과 외부 포트 개방은 V1에서 준비하고, 비밀번호나 개인키를 이 저장소 또는 대화에 넣지 않는다.
- 여러 사용자가 동시에 체험할 때: 브라우저별 저장소만으로는 VM 슬롯 중복을 막지 못한다. 공유 배정이 필요하면 서버 측 슬롯 예약·반납 기능이 필요하다.
- 실제 API 연결을 검증할 때: 백엔드가 `https://gsmsv-client-v2.vercel.app` Origin을 허용해야 한다.
- Serverless 실행, Database TCP 접속, Apps 배포, 인프라 전원 제어까지 실제 서비스로 만들려면 해당 백엔드 기능이 필요하다. 현재 범위는 이 화면들의 클라이언트 상태 기반 체험이다.
