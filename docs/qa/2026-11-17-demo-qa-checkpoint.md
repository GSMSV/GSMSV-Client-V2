# main 데모 QA 중간 기록

중단 요청: 2026-11-17. 사용자가 재개를 요청할 때까지 추가 테스트·수정·배포를 하지 않는다. 5시간 토큰 사용량 70% 초과 시 중단한다.

## 대상

- 배포: `https://gsmsv-client-v2-main.vercel.app/?demo=1`
- 브라우저: 사용자가 연 Chrome 데모 탭
- 목표: 학생·관리자 데모의 모든 주요 생성, 조회, 수정, 삭제, 승인 흐름과 Figma 화면 일치 확인
- 백엔드 `main` 도메인 허용 검증은 사용자가 완료를 알릴 때 재개

## 실제로 확인한 동작

1. 데모 홈이 열리고 VM·Serverless·Database·Apps 목데이터가 표시됨.
2. 홈에서 `portfolio-api` 14일 연장 클릭 → 만료일이 2026-10-03에서 2026-10-17로, 남은 기간이 4일에서 18일로 갱신됨.
3. 홈의 `VM 관리` 클릭 → VM 개요, 운영 정보, SSH 정보 표시됨.
4. Serverless 목록에서 `새 함수` 클릭 → 생성 양식 표시됨.
5. `video-demo-api` 생성 → 함수 상세로 이동하고 코드·버전·Trigger·환경변수·테스트·Logs 탭 표시됨.
6. 비활성 함수 테스트 실행 → 활성화 안내 대화상자 표시됨. 대화상자에서 `함수 활성화` 클릭.
7. 다시 테스트 실행 → `{ "message": "안녕하세요, 지민!" }` 성공 응답과 `Greeting sent 지민` 출력 확인.
8. Logs 탭 → 해당 실행 기록 표시됨.

## 확인된 문제·주의

- 새로 만든 `video-demo-api`의 코드 화면에서 만료 안내가 `생성 후 7일`, 연장 후 날짜가 `10월 20일`로 표시됨. 생성·버전 저장 시각은 실제 11월 17일이라 날짜가 서로 맞지 않음. 원인 후보: `ServerlessFunctionPage.tsx`의 고정 배너 문구와 `demoServerless.ts`의 고정 만료·연장 날짜. 재개 시 수정하고 실제 화면에서 재검증.
- 기존 Figma 커버리지 기록의 제품 화면 62개 중 전용 Database 신청 초기 상태는 부분 일치. 기본 목데이터에 이미 검토 중 신청이 있어 첫 방문에 새 신청을 바로 체험할 수 없음. 관리자 거절 후 재신청하거나 새 팀을 만드는 경로는 코드상 존재하며 실제 클릭 검증 필요.
- 브라우저의 실제 학생·관리자 전수 클릭과 Figma 화면 비교는 아직 완료되지 않음. 위 8개 동작만 실제 확인함.

## 재개 위치

- Chrome은 `video-demo-api`의 Logs 탭에 있음. 데모 상태는 사용자의 브라우저 로컬 저장소에 유지됨.
- 다음 순서: Database 생성·관리 → Apps 생성·서비스 → 팀 생성·승인 → VM 생성·전원·네트워크·스냅샷 → 관리자 처리 → 디자인/반응형 대조 → 발견 사항 수정·재검증.
- 작업 트리는 `sunwoo162/check-backend-progress` 브랜치에서 깨끗한 상태였음. 이 기록 파일만 새로 추가함.
